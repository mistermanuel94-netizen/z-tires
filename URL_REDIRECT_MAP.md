## Policy

1. **301 for content with a genuine successor.** Permanent, so link equity consolidates.
2. **410 for content that was fabricated or is a dead platform artefact.** The WordPress default
   post, its category and date archives, the author archive and the two RSS feeds have no
   equivalent page. Redirecting them to `/` would be a soft misdirection that tells a crawler the
   homepage is what that URL became. 410 Gone is the honest status and de-indexes faster.
3. **301 for theme demo content that has a real counterpart.** The eight fabricated staff profiles
   redirect to `/about/` and the twelve fabricated service pages to `/services/`, because a real
   page covering that *topic area* exists even though the specific content was fiction.
4. **Single hop, always.** The live site fed crawlers eight two-hop chains (for example
   `/scope/global/` → `/` → `/en/`). Every rule here points at its final destination.
5. **Never redirect a live path.** `/request-a-quote/` and `/thank-you/` exist on both the old and
   new site at the same path, so they carry no rule at all. They are listed in
   `UNCHANGED_PATHS` so the audit can tell "deliberately unmapped" from "forgotten".

## Two paths that need no rule

| Path | Why |
|---|---|
| `/request-a-quote/` | The legacy slug is reused as the canonical quote hub |
| `/thank-you/` | Unchanged |

## Verification

Redirect behaviour is verified against a running build, not just against the config file:

```bash
npm run build
npm run qa:serve &          # serve.mjs applies _redirects exactly as the host will
curl -sI localhost:4499/en/            # → 301 Location: /
curl -sI localhost:4499/en/about-us/   # → 301 Location: /about/
curl -sI localhost:4499/hello-world/   # → 410
curl -sI localhost:4499/nope/          # → 404
```

Confirmed at the time of writing:

```
301  /en/                 Location: /
301  /en/about-us/        Location: /about/
410  /hello-world/
404  /nope/
200  /robots.txt
```

## Launch checklist for the redirect layer

- [ ] Deploy with the host config that matches your platform (see table above)
- [ ] Spot-check 10 legacy URLs in production, including the two documents and the Terms PDF
- [ ] Confirm `https://flextyres.com/en/Terms%20&%20Conditions.pdf` now resolves — it 404s on the
      live site from a link in the header and footer of **every page**
- [ ] Submit the new sitemap in Google Search Console and Bing Webmaster Tools
- [ ] Keep the old property in Search Console for at least 6 months to monitor 404s
- [ ] Take the legacy root WordPress install offline once traffic has migrated
